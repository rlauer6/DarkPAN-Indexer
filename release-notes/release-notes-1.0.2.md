# DarkPAN::Indexer 1.0.2 Release Notes

## Overview

This is a major architectural overhaul of `DarkPAN::Indexer`. The module has been
essentially rewritten as a clean **orchestrator** that composes pluggable storage
and format engines, replacing the previous monolithic role-based design. The CLI
has been extracted into its own class and the indexer's public API is now a proper
Perl library interface.

---

## Breaking Changes

### `DarkPAN::Indexer` is no longer a CLI class

`DarkPAN::Indexer` no longer inherits from `CLI::Simple`. It is now a plain
`Class::Accessor::Fast`-based orchestrator with a library API. All command-line
handling has moved to the new `DarkPAN::Indexer::CLI` module.

**Before (1.0.1):** The module drove the `darkpan-indexer` script directly via
`CLI::Simple` commands (`cmd_index_darkpan`, `cmd_load_database`).

**After (1.0.2):** Use `DarkPAN::Indexer` programmatically, or invoke
`darkpan-indexer` (which now delegates to `DarkPAN::Indexer::CLI`).

### Removed modules

The following modules have been deleted:

- `DarkPAN::Indexer::Role::Indexer` — functionality absorbed into the new
  format/storage engine architecture
- `DarkPAN::Indexer::Role::Loader` — replaced by `DarkPAN::Indexer::Format::SQLite`
- `DarkPAN::Indexer::Role::Utils` — replaced by storage engine roles
- `DarkPAN::Resolver::SQLite` — removed from this distribution

---

## New Features

### Pluggable storage engines (`DarkPAN::Indexer::Storage`)

A new `DarkPAN::Indexer::Storage` role defines the storage contract. Two
implementations ship with this release:

- **`DarkPAN::Indexer::Storage::S3`** — S3-backed DarkPAN (replaces the
  hardcoded S3 logic from `Role::Indexer`)
- **`DarkPAN::Indexer::Storage::Filesystem`** — local filesystem DarkPAN, new
  in this release

Storage engines are selected via the `storage.type` key in the JSON config.
Legacy configs containing only an `AWS` block are automatically treated as S3
for backward compatibility. A fully-qualified class name can be specified using
the `+` prefix (e.g. `+My::Custom::Storage`).

### Pluggable format engines (`DarkPAN::Indexer::Format`)

A new `DarkPAN::Indexer::Format` role defines the index format contract.
`DarkPAN::Indexer::Format::SQLite` ships with this release (refactored from the
old `Role::Loader`).

Format engines are selected via the `format.type` config key and default to
`SQLite` if omitted.

### New public API

```perl
use DarkPAN::Indexer;

my $indexer = DarkPAN::Indexer->new( config_file => '/path/to/darkpan.json' );

# Full rebuild from every distribution in the repository
my $stats = $indexer->create_index;

# Incrementally re-index a single distribution (locked read-modify-write)
$indexer->update_index( distribution => 'authors/id/A/AB/AUTHOR/Foo-1.0.tar.gz' );

# Remove a distribution's packages from the index
$indexer->delete_from_index( distribution => 'authors/id/A/AB/AUTHOR/Foo-1.0.tar.gz' );
```

All three index operations acquire a storage lock for the duration of the
read-modify-write cycle.

### `DarkPAN::Indexer::CLI` (new)

CLI concerns extracted from `DarkPAN::Indexer` into a dedicated
`DarkPAN::Indexer::CLI` module. The `darkpan-indexer` script now delegates to
this class.

### Config file support for YAML

`_load_config` now supports open filehandles as well as `.json` and `.yaml`/`.yml`
file paths. YAML support requires the optional `YAML::Tiny` module.

Four new test scripts have been added:

- `t/03-update-index.t` — incremental index update tests
- `t/04-update-index-failure.t` — error handling for update failures
- `t/05-update-index-missing-index.t` — behaviour when no index exists yet

## Build System

- `test-requires.raw` generation now subtracts the distribution's own
  `provides` list, preventing self-referential test dependencies from
  appearing in `test-requires`
- `extra-files` is now generated by `CPAN::Maker::Bootstrapper` from
  `buildspec.yml` rather than being an empty stub
- `extra-files.mk` inclusion is skipped during bootstrap builds
  (`BOOTSTRAP_BUILD` guard)
- `.includes/bootstrap.mk` added as a new managed include file
- Fixed a stray trailing semicolon in the `$(MODULE_PATH).in` recipe
